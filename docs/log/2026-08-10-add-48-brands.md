**Date:** 2026-08-10 · **Status:** done

## Goal

Tina listed 49 brands from `data/brand-candidates-2026-08-07.csv` and asked for all of them.

48 added, **47 publishing 9,645 pieces**. Two of the 49 did not go in:

  have been a silent no-op: a brand in the file that publishes nothing.
- **`zuhre`** — added and ingested (176 rows) but publishes 0: every product is out of stock.
  Not a curation problem; the pipeline correctly refuses to publish what cannot be bought.

## What went in

`data/brands.ts` (+48, and 16 `city` values cleaned — see below), `data/translate-brands.json`
(+10 non-English brands), and the regenerated data files.

Fields came from the CSV rather than being invented, but **every feed was re-probed on the day**
rather than trusted from a 3-day-old file: JSON parsed and a `products` array confirmed, because
HTTP 200 proves nothing (§10.3). One "dead" feed (`nihan`) was a transient failure and was fine
on re-probe; only `modesque` is genuinely blocked.

## Five things that fired, in order

### 1. zsh ate the argument list (§10.20, again)

`npx tsx scripts/add-brands.mjs $SLUGS` reported *"Unknown brand slug(s)"* for all 48 — because
**zsh does not word-split unquoted parameters**, so the script received ONE argument containing
all 48 names. The giveaway was the error printing them space-separated when the code does
`join(', ')`. `set -- ${=SLUGS}` fixed it. This is the third variant of §10.20 in the log.

### 2. I put prose in a field that renders

The CSV's `city` column holds the scout's evidence, not a place name. Copying it wholesale put
**a phone number and an email address into `city`** — which renders on `/designers` next to the
brand name. 16 values cleaned to place names. The lesson is narrow and reusable: a CSV column
and a typed field can share a name and mean different things.

### 3. The classifier is wrong on Turkish, and the bug is not Turkish

Measured after ingest, per §10.16. Turkish brands came out 70–85% one garment, which is not what
a modest-fashion catalogue looks like. Sampling the rows:

- `Pantolon Tunik Takım` (a trouser-and-tunic **set**) → trousers
- `Krem Kuşaklı Kısa Bluz` (a **blouse**) → trousers
- `Tesettür Elbise` (a modest **dress**) → **set**

The cause is in `lib/tag.ts`:

```js
['trousers', /trouser|pant|jean|legging|culotte|wide.?leg/i],
['set',      /set|co.?ord|two.?piece|coordinate|\bensemble\b/i],
```

Neither `pant` nor `set` is word-bounded, though §10.10 records that class as fixed. `set`
matches inside **Te-set-tür**, which appears in a large share of Turkish modest titles. Proven
by running the real regexes — and it is **not only Turkish**: `Closet Staple Dress` and
`Sunset Kaftan` both match `set` today.

**Deliberately NOT fixed in this pass.** Changing a `GARMENT_RULES` entry silently reclassifies
across all 109 brands, and per §10.12 it only takes effect on re-ingest — so it needs a
before/after measurement and regression tests from real titles. ~1,229 published Turkish rows
are affected. Raised with Tina; it is the next job.

### 4. Four tests went red, and one would have broken production

Running the suite before pushing (not after) caught:

| failure | cause | fix |
|---|---|---|
| CSP `img-src` | the 3 WooCommerce brands serve images from their **own** domains, not `cdn.shopify.com` | 3 hosts added to `next.config.ts` **and** `ALLOWED_IMAGE_HOSTS` |
| FX coverage | 8 new currencies had no rate | `fetch-rates.mjs` now DERIVES its list from `brands.ts` |
| price expectations | TRY, KWD, QAR, DKK, NOK, SEK, IDR, SGD | explicit assertions, read from what `formatPrice` actually returns |
| required field empty | 12 rows priced **0** (İpekstil "Kombin Kutusu" outfit-box configurators) | `build-data.mjs` drops price-0 rows |

The CSP one is the one that mattered: those images render fine locally and are **blocked by the
browser in production**, silently, on every product of three brands.

`fetch-rates.mjs` carried a literal list plus a comment asking the next person to *"keep in step
with data/brands.ts"*. It was not kept in step. It derives now, so it cannot drift again — read
as text, not imported, because that script runs under plain `node` (Invariant 7).

### 5. A men's product published, because exclusions run before translation

`lib/exclude.test.ts` failed only AFTER translation ran: raw title `Box ramadan homme - bleu`
became `Men's Ramadan box - blue`. Exclusions are evaluated on the **original** title; translation
happens later at publish. So an English-only gender filter is blind to foreign menswear **by
construction** — §7 is a binding editorial rule and this bypassed it.

Fixed at the language, not the ordering: men's-wear words for all seven languages the catalogue
now carries (fr/nl/de/it/da/tr/id), each `\b`-anchored (§10.5), and **each measured against the
whole raw catalogue before adding** (§8) — French matched 1 (the leak), the other six matched 0.

## The near-miss that mattered most

Between starting the pipeline and going to push, `origin/main` moved **2 commits ahead**: the
**nightly catalogue refresh** (`0d506e5` — +20 new, 78 delisted, 15,448 updated) and another
session moving translation into `build-data.mjs`.

My `products.json` and `raw-products.json` were built on the older base. **Committing them would
have reverted the entire refresh** — 78 delistings undone, 15,448 updates lost, 561 translated
titles reverted — under a commit message about adding brands. That is §10.1 in a new costume: a
bulk write undoing work it never knew about.

Recovered without a re-scrape, because the 48 slugs were provably absent upstream:

1. backed up all seven of my data files
2. asserted **zero overlap** between my 48 slugs and the refreshed raw
3. discarded my data files, fast-forwarded to `origin/main`, kept only the two source edits
4. grafted my 11,569 rows on: 21,920 + 11,569 = 33,489, with an id-collision assertion
5. merged decisions additively — **0 existing decisions overwritten** (Invariant 14)
6. republished

One casualty and its recovery: step 3 also discarded `title-translations.json`, losing 2,437
cached translations. The backup had them; merging restored **1,722** rather than re-hitting the
translation endpoint.

**Rule this earns:** for any long data operation, `git fetch` immediately before the *pipeline
run*, not just before the push. A nightly bot can land inside the window, and by then the whole
build is against a stale base.
