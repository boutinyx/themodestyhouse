# Add Zayda (Australia) to the catalogue
**Date:** 2026-08-07 · **Status:** done

## Goal
Tina asked for `zayda.com.au` to be added.

## Verification before adding
- **Site live**, Shopify, `products.json` → HTTP 200.
- **Catalogue is 2 products — the entire shop.** Confirmed three ways so this is
  not a paging artefact: `?page=2` returns 0, `/collections/all/products.json`
  also returns 2, and `sitemap_products_1.xml` has 1 entry.
- **Photography is why it earns a place**: 6 images per product, **12 of 12
  portrait**, widths 1023–4284px.
- **Shipping is LIMITED, not worldwide.** Quoted from
  `/policies/shipping-policy`: *"ZAYDA ships to addresses within Australia and to
  selected international destinations."* Customers pay their own duties.
- No men's, kids' or non-apparel rows.

## What changed
- `data/brands.ts` — one entry, with the two-product catalogue and the shipping
  limitation recorded in a comment so neither has to be rediscovered.
- Ingested (`add-brands.mjs zayda`) and published (`build:data`).

## A correction made mid-task
`community` was first set to `general`. That was wrong: `general` is used for
exactly two brands (Bouguessa, HUM) that are not hijab-specific, whereas Zayda's
own photography is explicitly hijabi. It also has a functional consequence — the
`/hijabi-outfits` lane matches `community === 'hijabi'`, so `general` would have
silently excluded the brand from it. Corrected to `hijabi` and **re-ingested**,
because `normalizeProduct` copies `community` from the brand record into every
row at scrape time; editing `brands.ts` alone would not have changed the data.
