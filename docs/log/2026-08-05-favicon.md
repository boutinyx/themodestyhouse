# Ship the real favicon
**Date:** 2026-08-05 · **Status:** done

## Goal
Install the brand favicon (aubergine rounded square, TM monogram) supplied by Tina.

## What changed
- **`app/favicon.ico`** — replaced with the supplied file. 2,619 bytes, three
  frames: 16×16, 32×32, 48×48 (was 25,931 bytes).
- **`app/icon.png`** — deleted.

## Why icon.png had to go
Dropping the new `.ico` in on its own would have changed nothing visible. Next's
file conventions emit **both** `app/favicon.ico` and `app/icon.png` as `<link
rel="icon">` tags, and the live site was serving:

```
<link rel="icon" href="/favicon.ico" sizes="256x256" type="image/x-icon"/>
<link rel="icon" href="/icon.png"    sizes="707x992" type="image/png"/>
```

Browsers generally prefer the larger declared size, so the 707×992 PNG won — a
**non-square** 315 KB image being used as an icon. Nothing in `app/`,
`components/` or `lib/` referenced it (the header crest is `/logo.png`, a
separate file), so removing it was safe.

## Verification
`npm run build` → compiled successfully; the emitted markup now contains exactly
one icon link:

```
<link rel="icon" href="/favicon.ico?favicon.0clzphduiv9cd.ico" sizes="48x48" type="image/x-icon"/>
```

## Notes / follow-ups
- The supplied `.ico` tops out at **48×48**, which covers browser tabs but is too
  small for an Apple touch icon or a PWA home-screen icon — there is now no
  high-resolution icon at all. If those matter, export the mark at **512×512 PNG**
  and it can be wired in as `app/apple-icon.png` and `app/icon.png`. Upscaling the
  48×48 would look poor, so this needs the original artwork rather than a resize.
