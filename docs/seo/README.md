# SEO snapshots

Dated captures of what Google actually does with this site. Generated by
`node scripts/seo-snapshot.mjs [--days N]`, one JSON per run, committed.

## Why

The 2026-08-19 audit shipped ~20 changes, each carrying a "how would we know
this failed?" check. Those checks are worthless without a **before**. This is
the before; every later run is a comparable after, and the history lives in git
rather than in someone's memory.

It also answers, in one place, questions no single tool answers together:

- did the 10 `?type=` subtype pages ever get indexed?
- did the 5 lanes submitted on 2026-08-19 leave "Crawled — currently not indexed"?
- did impressions move on the three lanes chosen for deeper copy
  (`/modest-abayas`, `/modest-dresses`, `/modest-hijabs`)?
- did page weight creep back up as the catalogue grew?

## Requirements

Search Console has **no API key path** — it needs a credential that asserts a
person. Set up once:

```bash
gcloud auth application-default login \
  --scopes=openid,https://www.googleapis.com/auth/userinfo.email,https://www.googleapis.com/auth/cloud-platform,https://www.googleapis.com/auth/webmasters.readonly
gcloud auth application-default set-quota-project project-c18afb0a-80a5-42dd-97b
```

The `x-goog-user-project` header the script sends is **mandatory** — without it
the API returns 403 "requires a quota project", which reads like a permissions
problem and is not one.

## Reading a snapshot

`coverage` is Google's state **at capture**, which lags deploys by days — a URL
published this morning is legitimately "unknown to Google" this afternoon. Never
read a fresh snapshot as a verdict on a same-day change.

`weight` is deliberately measured with `accept-encoding: identity`. The wire cost
is ~4x smaller after compression; the number that matters is what a phone has to
parse, and compression does not reduce that.

Prices and currencies are not captured. Per ADR-0002 the site never presents a
single converted figure, and a snapshot should not invent one.

## Baseline — 2026-08-19

Captured hours after the Tier 1 + Tier 2 SEO work deployed, so it reads as
"the moment the work landed", not "before the work started".

```
5 clicks · 219 impressions · CTR 2.28% · avg position 37.5   (365-day window)
sitemap 35 URLs — 20 indexed, 10 unknown, 5 crawled-not-indexed
```

- The **10 unknown** are the `?type=` subtype pages, live for a few hours.
- The **5 crawled-not-indexed** are the lanes submitted by hand that afternoon.
  They had been "Discovered — currently not indexed" or "URL unknown" that
  morning; **being crawled is one step further on**, and it happened within
  ~90 minutes of the requests. Whether Google then keeps them is the open question
  this file exists to answer.

## What a good next capture looks like

Run again in **4–6 weeks**. Judge it on, in order:

1. Are any of the 5 lanes now `Submitted and indexed`?
2. Are any of the 10 subtype URLs known to Google at all?
3. Did impressions rise on the three deepened lanes specifically, against the
   others as a control? That comparison is the entire point of only deepening
   three (Tier 2 item C) rather than all fourteen.
